# 工作室本地服务

## 系统任务承载与监控纳管（2026-10-15）

Windows正式常驻应复用 `studio-service-windows.ps1` 的 Install/Start/Status/Stop/Uninstall，以明确项目归属的系统任务承载guardian。只使用隐藏窗口、detached或看到父终端退出后仍活着，不能证明脱离上层工具的Windows Job；实际任务启动后还需核对祖先、Job归属和健康状态。新任务不接管未知进程，也不替代物理开机验证。

任务可显式提供非秘密 `-OpsDirectory 私有绝对目录 -OpsEnvironment local`，宿主将配置传给guardian和自建子进程，统一私有事件库。正常本机启动若存在有效 `.ops/local-monitor.json`，会校验原库/回环端口/本机只读绑定并将原monitor作为第四个服务纳入既有有限恢复；独立旧monitor占口时拒绝。监控只因自身进程/采样失效恢复，不因API业务故障循环重启；停止走自建进程的随机控制身份。

本机配置 `backups.enabled` 只接入原SQLite一致性备份调度，周期、保留份数及私有目录须合法；本机接线不启用远端或真实告警。示例配置、实际启用及目标正式环境仍分别验收。当前恢复记录和可用入口见 `docs/系统任务恢复与正式上线准备-2026-10-15.md`；以下旧版本启用状态保留原验收时点。

## 2026-10-15 本地连接与启动修复

日常本机使用根目录 `启动本地后台.cmd`，或 `pnpm local`。它打开当前两端生产构建及接口，保留已有 `.data/studio.sqlite`（或原 `STUDIO_DB_PATH`）及账号密码；缺库/缺构建时拒绝启动，不另造空库或覆盖数据。后台 http://127.0.0.1:3006/，接口3007，独立打手 http://127.0.0.1:3008/。启动器脱离调用终端运行，终端退出后仍保留服务；接口不使用源码watch，编辑文件不会自动打断日常连接。开发时仍可显式 `pnpm dev` 使用热更新，已有端口时拒绝重复启动。

监管器只管理自己创建的进程：单端意外退出只重启该端，每60秒最多5次恢复，持续失败记录为failed并保留另外两端，不无限重试。只在显式关闭监管器时结束它拥有的服务；不按node进程名批量终止、不接管未知端口。127.0.0.1:3009为监管器独占及只读身份握手，OS在进程结束时释放；nonce核对避免旧PID文件误认和并发重复启动。该握手不包含业务数据、密码或推送配置，不改变认证及业务权限。

`pnpm local:status` 读取监管器身份、端口、进程状态及日志位置。启动成功还需后台/打手HTML与两端代理及直接API的匿名session正确回应；原GET session匿名返回200和user:null，不能误当401失败或把HTML兜底当API成功。启动/退出/信号/恢复原因和各端stdout/stderr保存在 `.qa/local-service/`，不打印环境或完整请求。日志等待child.close和写入完成，日志/状态写入错误受控处理。当前正常入口加载已构建页面；以后UI改动须重新构建再启动或在显式开发模式验证，后台计算修复需正常重新加载接口。

旧开发启动脚本任一子exit即连停三端、且旧日志没有最终退出原因，已改为单端隔离恢复。旧日志确有源码/依赖变化造成API自动重启，但不能从这些记录断言本次三端最终退出的具体触发因素。连接修复未变更界面、资金/权限/Actor/会话规则。上节统计优化与压力记录保留其对应源码；本轮仅启动机制及隔离生命周期验证，未将日常库用于压力。详见 [本地连接修复记录](../docs/本地连接与启动修复-2026-10-15.md)。

## 启动

在项目根目录运行：

```powershell
node server/index.mjs
```

默认监听 `http://127.0.0.1:3007`。开发前端通过 Vite `/api/studio` 代理连接此服务；构建前端后，此服务也会从 `dist` 提供网站及页面刷新回退。

首次启动创建 `.data/studio.sqlite`。初始账号为 `admin`，初始密码使用环境变量 `STUDIO_ADMIN_PASSWORD`；未设置时生成随机密码，仅写入 `.data/bootstrap-password.txt`，不会输出到终端。环境变量只在空数据库初始化时生效，不覆盖已有密码。初始账号角色为超级管理员（`super_admin`），拥有全部权限；普通管理员（`admin`）默认不开放财务、工资和利润，不能维护超级管理员账号。旧版初始 admin 自动迁移为超管，保留原业务、密码及会话。

默认初始化少量明确标记的演示人员、客户、模板和一笔演示订单。演示员工和打手没有预设可登录密码，需要管理员重置。底薪和比例为空，必须由财务配置。首次建立空业务数据库可在启动前设置 `STUDIO_DEMO=false`，仍保留管理员及已确认的基础来源和金盾电竞店铺。正式使用前应停服备份演示数据库，再单独建立真实业务数据库。

可配置：

| 环境变量 | 默认值 / 用途 |
| --- | --- |
| `STUDIO_HOST` | `127.0.0.1` |
| `STUDIO_PORT` | `3007` |
| `STUDIO_DB_PATH` | `.data/studio.sqlite`，可以指向独立数据库 |
| `STUDIO_ADMIN_PASSWORD` | 空数据库初始化密码，至少 8 位 |
| `STUDIO_DEMO` | `false` 关闭首次演示数据 |
| `STUDIO_ALLOWED_ORIGINS` | 额外可信网站 origin，逗号分隔；默认允许同源及本机开发代理 |
| `STUDIO_SECURE_COOKIE` | HTTPS 部署设置为 `true` |
| `STUDIO_AUDIT_RETENTION_DAYS` | `90`，热日志保留天数；到期移入归档，不自动删除 |
| `STUDIO_AUDIT_HOT_MAX_ROWS` | `10000`，热日志行数上限；超出部分移入归档 |
| `STUDIO_AUDIT_ARCHIVE_MAX_BYTES` | `524288000`（500 MiB），归档 JSON 内容字节容量上限，达到时阻止业务写入 |
| `STUDIO_PUSH_PUBLIC_KEY` | 网页推送 VAPID 公钥，未配置则仅站内消息 |
| `STUDIO_PUSH_PRIVATE_KEY` | VAPID 私钥，仅服务端秘密配置，不写入源码或交付文档 |
| `STUDIO_PUSH_SUBJECT` | VAPID 联系地址，mailto 或生产 HTTPS URL |
| `STUDIO_PUSH_ALLOWED_HOSTS` | 可选额外可信推送服务主机，以逗号分隔；默认允许 Apple、FCM、Mozilla、Windows 推送服务 |

## 打手端 1.0

手机前端现为独立 `player-client/` 工程，默认 `http://127.0.0.1:3008/#/player/login`，代理 `/api/studio` 到本服务 3007；管理后台仍为 3006 和根目录 dist。账号由后台创建或重置密码，两端共用数据库和业务规则。打手渠道 `X-Studio-Client: player` 使用 `studio_player_session`，管理后台使用 `studio_session`，登录和退出互不覆盖；打手渠道只允许 player 角色。完成截图、私人收款码、钱包、退单和提现都连接真实数据库。前台打开时自动核对数据，服务端每 30 秒处理指定超时及持久推送队列，进程重启后恢复。

独立启动：`pnpm dev:api` 和 `pnpm dev:player`；全套启动 `pnpm dev`，构建使用 `pnpm build:all`，分别生成 root dist 和 player-client/dist。独立静态代理启动 `pnpm start:player`，配置 `STUDIO_API_TARGET`（默认本服务 3007）、`STUDIO_PLAYER_HOST/PORT`（默认 127.0.0.1/3008）。远程生产前端 Origin 需加入本服务 `STUDIO_ALLOWED_ORIGINS`。详见 [独立前端说明](../player-client/README.md)。

推送未配置时页面明确说明，并保留站内消息；配置了推送也不代表中国大陆所有手机必达。实际安卓/iPhone 授权、关闭网页、锁屏和网络效果需在目标设备验收。PWA 的 Service Worker 不缓存业务接口、金融请求或附件。

新增字段使用兼容默认值，不清空旧订单和财务数据；旧提现没有收款快照时保留“历史资料未知”。不应把当前测试数据库作为正式数据库。配套接口和状态详见协作契约。

完整备份示例（目标文件必须不存在，包含全部附件、账本、审计与消息）：

```powershell
node scripts/studio-backup.mjs .data/studio.sqlite .data/backups/studio-2026-10-13.sqlite
```

备份通过 SQLite 在线一致性复制和完整性检查，旁边生成不含密码的元数据 JSON。正式切换前在隔离目录用备份副本启动服务核对订单、金额、附件及权限；恢复时先停服务并另存当前库，不能用旧备份覆盖上线后新增交易。回滚需同时保留新数据库与新资金记录；1.0 增加状态/字段后，旧代码不能直接处理 canceled/unassigned 和奇数分分账。

## 数据与接口

接口与字段见 [协作契约](../docs/STUDIO-CONTRACT.md) 和 [源码类型](../src/types/studio.ts)。所有业务写入在 SQLite `BEGIN IMMEDIATE` 事务中完成，数据和审核日志同时提交；业务主体保存在状态行，客户关联编号与操作日志使用独立表，附件以数据库 BLOB 存储，会话只存令牌哈希。旧状态 JSON 中的日志自动迁移到日志表，保留原记录。金额使用整数分，比例为万分比，日期统计使用 `Asia/Shanghai`。

密码使用独立随机盐和 scrypt 哈希；会话持续 12 小时，Cookie 带 `HttpOnly`、`SameSite=Lax`。停用账号立即失去接口权限，重置密码或更换角色撤销已有会话。附件限制 PNG、JPEG、WebP，最大 8MB，并检查签名、登录身份及记录关联可见性。前端隐藏权限与服务端权限检查分别执行；客服响应不含工资、利润或计提比例快照。

工作室外观使用 `/appearance` 读取、保存与 `/appearance/reset` 恢复默认，修改需要 `settings.manage` 并携带当前版本；并发冲突返回 409。支持品牌、业务页/总览背景、预设图标、登录页文案/背景及玻璃样式。启用的品牌图片和业务背景可供已登录成员读取，配置管理员可预览配置中的未启用图片。外观共享只授予图片下载权限，不能用于复用他人的订单、财务等凭证。界面临时预览不写数据库，保存或恢复会同步记录脱敏操作日志。匿名 `/appearance/public` 只返回品牌名称、Logo、登录页和玻璃样式；`/public-assets/:id` 只允许读取当前保存的 Logo 和启用的登录背景，其他业务图片及上传接口仍需认证。

## 来源、订单与打手财务

来源使用可配置的 `Platform.rules` 四项开关：需要店铺、需要平台单号、需要付款凭证、允许落地付。旧配置未设置规则时沿用初始默认：闲鱼需要店铺和平台单号、不强制凭证；游戏大厅需要凭证、允许落地付；其他来源需要凭证。管理员可修改这些规则，不再将下单校验固定写死为平台名称。所有来源都可建店铺，店铺名称仅在同一平台内唯一；已用于订单的店铺不能改所属平台。

客户档案可保存主要来源，并通过独立增删和分页接口维护多个平台订单号；只有要求平台单号的来源允许添加此类关联记录，按该来源规则校验店铺。关联编号不创建业务订单、不增加营收，也不限制固定 10/20 条总数。新订单不再录入沟通渠道 `channel`，服务端新建值为空，历史原值保留。

打手独立手机页面和 `/player/*` 接口连接真实服务及数据库，支持接单、拒单、退单、完成材料、钱包、收款资料、提现、排行及消息。直接指定仍为待接单，须本人接受；公共池受等级延迟控制。退回验收保留原负责人，不因接单上限拒绝退回，但超限时不能接新单。后台授权状态更正可以免截图登记，普通打手上报仍须截图。双人整数分报酬平分，奇数分多出的 1 分归负责人，结算、更正和诊断保持一致。

补充订单操作 `action=edit` 供有 `orders.edit` 的账号编辑尚未完成、未取消的订单信息及金额；金额变更必须说明原因。`action=adjust` 供财务更正完成或取消订单。金额更正与实际退款分别留痕：更正已录收款金额会同步更新原付款日报；实际退款必须走退款记录。

`action=correct-status` 只允许财务、店长、老板、超级管理员四类角色且具备 `orders.edit` 的账号执行，必须填写原因；普通管理员即使获得订单编辑权限也不能执行。五种状态可相互更正，无需完成截图；进入待验收或直接完成会保存后台登记来源、登记人和原因，验收页、导出及数据检查共同识别。已有同一打手的截图复核时可沿用，保留原审核历史；打手端正常上报仍须截图。后台更正不受接单上限或历史打手停用影响，但执行、验收和完成须有真实负责人，完成仍须足额收款。店长默认不增加其他财务权限。已结算状态回退通过冲正流水处理，保留原完成月份和已付提现；恢复只沿用原结算人员与报酬，避免重复发放。取消导致的零报酬与人工明确改价分别保存，重开恢复原报酬时不覆盖财务明确改价。

经营收入、退款和订单成本归属原付款日；客服、运营工资佣金归属完成月份。完成时保存计提比例及运营归属；缺失比例可在补齐有效配置后填入，已有比例不随未来方案修改。平台运营提成开关不再使用，由工资方案 `platformRates` 控制：非大厅平台 0 表示不参与，null 表示待配置；游戏大厅运营提成固定为 0。固定工资方案对应佣金为 0，历史快照不因新方案重新计算。日报利润不扣月度底薪，月报扣底薪；任意日期概览仅在完整月份区间另提供含底薪利润，未验收预计成本和缺配置均明确标示。

工资发放保存快照。发放后新增退款只记录新增多发佣金差额，已按退款净额计薪的不再扣回；同一月份如产生新的已完成订单佣金或新的退款差额，允许登记补充结算，补充行底薪为 0。重复发放且没有新增项目会拒绝。已结算月报的底薪采用发放快照。当前月中更换方案不做底薪按天折算，以该月份最新生效方案确定尚未发放的月度底薪；按工时计薪暂不开放。

已提现后的退款或报酬减少会标记财务人工核对。系统不会自动扣减已提现打手的余额、建立负余额或自动追回款项；财务通过退款 `resolve` 留存处理说明，实际追回或抵扣按线下人工确认结果执行。没有已付款提现但有占用中的提现时，报酬减少不能导致不足覆盖在途金额，须先处理相关提现。

新增 `/player-adjustments` 扣补款与处理结果接口需 `finance.withdrawals`。补款进入可用余额；扣款只扣现有可用部分，超额登记待追回，不触碰在途或已付款提现、不自动从未来收入扣回。财务可登记线下已追回或说明免除，独立流水保留原金额、实际扣款和人工差额。人工扣补款计入财务统计，订单状态冲正流水由原订单成本口径处理，避免重复计算。旧报酬更正留下的人工差额还可通过 `/reward-reviews/:id/action` 登记说明。

## 储值与独立押金

资金账户和不可直接改删的流水存于 `fund_accounts`、`fund_transactions`，幂等请求保存在 `financial_requests`。金额仍为整数分，资金、业务和审计在同一事务；失败或日志容量 503 时全部回滚，不留下半笔资金或成功请求缓存。余额为从 0 开始的实际登记值，不凭历史订单补造充值。

客户储值接口为 `/customers/:id/balance`、`/customers/:id/transactions` 和 `/customer-transactions`。余额供下单及原客户查看权限读，明细与充值 / 非订单扣款 / 退回需 `finance.refunds`。打手押金为 `/players/:id/deposit`、`/players/:id/deposit-transactions` 和 `/player-deposit-transactions`，财务 `finance.withdrawals` 可操作；本人只查看自己的押金。日常报酬补扣沿原 `/player-adjustments`，不抵押金；押金退还 / 没收仅接受退店或跑路场景。

资金写入 `requestId` 必填；原报酬补扣兼容旧无编号调用，提供编号后同样幂等。相同编号、操作者、路径和内容返回原结果，变化返回 409；每次重试先检查当前授权，撤权不能读取旧成功缓存。新储值订单和后续收款 `paymentMethod='balance'` 必须带编号，余额足够才全额扣款；支付客户指针和流水保存在订单，退款通过唯一退款来源原路回存，不重复现金退。已支付储值金额 / 方式不能裸改；原现金及大厅退款规则保持。

客户充值、押金缴退不计营业额；客户非订单扣款和退出押金没收计 `otherIncome`，按流水登记日进入日 / 月经营利润及区间概览。订单余额消费仍只在订单原付款日计一次收入。独立客户 / 押金账户、流水与员工 / 打手分开档案纳入原四类周期导出，加上固定班次及打手拒单/退单后完整目录 37 模块，逐模块 / 字段授权、筛选先于上限。

人员管理一级菜单分员工、老板（客户）、打手和考勤。打手 `playerAccess.login/claim/withdraw` 旧配置默认 true；关闭登录撤销会话，关闭新接单 / 提现不回写历史。新派单不指定无法登录或接单的账号；有未完业务、未结资金、在途或人工差额的打手不能换角色隐藏资金。资金只读诊断核对总账 / 余额、逐笔当时余额、储值订单支付及原路退款对象，不写新表或迁移日志。

## 工资、考勤与导出

`POST /work-schedules` 需 `attendance.manage`，接受 `userId/effectiveFrom/enabled/start/end/remark`。上、下班时间为 HH:mm，允许跨夜，不允许相同时间；从今天或之后生效，同一人员同一生效日唯一。停用设置以新版本表示，不删除历史。`bootstrap.workSchedules` 按考勤管理、全员工资或本人范围返回；日考勤优先于该日有效的固定班次，默认排班不生成实际工时或工资。数据检查核对人员关联、日期、有效时间及重复版本；导出保留可见配置版本，可按生效日期筛选。

登录页左图由 `login.illustration={mode:'default'|'image',image}` 独立设置，旧配置自动使用原默认图。与整页背景、标题和说明分别保存。匿名附件仅额外开放当前保存且启用的登录左图，移除或恢复默认会撤销该图片匿名访问；草稿上传仍是私有。纯色背景下展示区文字按背景选择可读颜色。

工资方案维护需 `salary.manage`，全员月结还必须具备 `salary.all`，仅本人查看权限不能用于全员发放。缺少底薪或应配比例时禁止月结；历史发放快照及新增差额补结算规则继续保留。

考勤界面未登记日期默认展示正常，不自动创建记录或虚构班次/到岗工时。`normal`、`rest` 可不填班次；填写时开始/结束须成对。正常状态的实际工时单独登记，无班次时可登记 0–24 小时，有班次时不超过班次时长；`hoursRegistered=false` 表示未登记。未来的正常/休息只是排班计划，实际工时只能为 0 或未填；休息、请假、缺勤不计实际工时。原 `scheduled`/`present` 状态为兼容保留，按工时计薪仍不开放。

报表支持日报、自然周（周一至周日）、月报及截至今天的总计报表，按当前权限提供目录、预览与下载。导出需 `reports.export`，客服及客服主管即使个人覆盖授权也硬性禁止；其他角色默认有此权限，但具体模块/字段仍受业务查看权限控制。预览每表 20 行，筛选后的全量下载上限 100,000 行，超过明确拒绝。来源编号和游戏 ID 保持字符串，导出金额换算为元、比例换算为百分数；待配置不伪装为 0。

## 日志容量与完整备份清理

`GET /logs` 按来源、人员、实体、记录号、动作、关键词和日期筛选并分页，`GET /logs/:id` 读取审计详情。读取及普通报表导出按当前权限对白名单字段投影，操作日志权限不授予金融明细或账号权限查看权。普通日志 Excel 是可见内容导出，不能替代完整恢复备份。

`GET /logs/storage` 和主动归档 `POST /logs/maintenance {action:'archive'}` 需 `settings.manage` 与 `logs.view`。默认热日志保留 90 天/最多 10,000 行，超过任一条件的较旧记录移入归档。主动归档无候选返回 0，不新增维护审计；成功时返回实际总移动条数，包括本请求审计写入触发的额外自动归档。界面显示本次条数及零条原因，切换日志来源立即查询。归档内容达到 90% 容量告警，超过可容纳的上限时业务事务返回 503 且全部回滚。容量统计指归档 JSON 内容字节，不代表整个 SQLite 文件、附件或 WAL 的磁盘上限。不会自动删除财务历史，也不将容量无限扩张。

完整原始 JSON 备份及清理需同时具备：`settings.manage`、`logs.view`、`reports.export`、`orders.view`、`users.manage`、`salary.all`、`profit.view`、`finance.review`、`finance.refunds`、`finance.withdrawals`、`finance.expenses`。默认老板/超管满足，普通管理员不满足。流程如下：

1. `GET /logs/archive-backup?beforeDate=YYYY-MM-DD` 流式下载该上海日期零点之前的归档原始 JSON；响应 `X-Studio-Backup-Token` 和 `X-Studio-Backup-Count`，不先把整个归档载入内存。
2. 等下载完成并保存文件后，`POST /logs/maintenance` 提交 `{action:'purge-archive',beforeDate,backupToken,backupConfirmed:true,reason}`。
3. 凭据有效期 30 分钟，绑定下载账号、截止日期及备份时归档范围。未完成、过期、换账号/日期、归档后来变化或重复使用均拒绝；仅勾选确认不能清理。清理操作仍留维护审计。

正常登录的会话创建与审计在同一事务，失败不留下不可用会话。仅当失败明确为日志容量 503，且正确密码账号具备上述完整备份权限时，允许登录维护；响应可带 `maintenanceNotice`。应急登录只在独立安全日志记录操作人、时间和会话账号，最多 1,000 条、保留 30 天，不存密码/token/财务内容；热日志及全量日志列表可查看此记录。`storage.maintenanceMode` 和 `warning` 标明维护状态，其他业务写入仍受 503 限制。完整备份清理后普通审计成功即退出维护状态。普通账号不能借此登录绕过容量限制，其他审计错误也不能被吞掉。

## 当前界限

本服务尚未部署公网。SQLite 状态结构适合当前单工作室使用；多实例扩容前应迁移实体表和服务端会话管理。公网部署时需要 HTTPS、受控 origin、定期数据库备份和真实账号配置。归档 JSON 备份保留原始审计内容，但不能替代完整 SQLite 数据库备份。

原源码 `src/views/safeguard/server/index.vue` 的随机数和示例 IP 已明确标为演示，开关机按钮禁用。授权老板/超管可读取 `GET /api/studio/runtime/metrics` 的真实请求耗时、错误、进程、磁盘/WAL、日志、推送积压及备份状态。`GET /api/studio/diagnostics` 继续只读检查业务数据，不执行远程命令或自动修复。运行配置、计划备份、引用安全回收及离线恢复步骤统一见 [稳定性共享契约 v3](../docs/STUDIO-CONTRACT.md)。

检查涵盖关联记录、订单状态与金额、打手报酬冲正、钱包及提现占用、客户平台编号、工资快照和实际工时；配置未齐及人工差额列为待核对，不当作损坏。响应只返回检查概要和至多 100 条异常 / 提醒，异常优先，总数不截断。请求和鉴权均只读，不修改业务、审计或旧日志，不重算历史工资；不能替代线下付款核实。仍没有真实主机 `health`、远程命令或自动修复接口。

# 本机 API 切换与监控

日常业务库和账号保持原路径。仅重载 API 时，应先用现有一致性备份工具生成新文件、验证完整性，再核对 API 的端口、父进程、命令和创建时间；不要停止三端管理器或按进程名结束服务。旧管理器没有单端优雅控制入口时，须记录该限制及准确的单进程切换，不能宣称完成了新守护器迁移。

本机独立监控复用 `scripts/studio-monitor.mjs`，实际配置放私有 `.ops/local-monitor.json`，状态查询：`node scripts/studio-monitor.mjs --config .ops/local-monitor.json --status`；停止：同入口改为 `--stop`；启动：去掉状态参数。命令必须在项目目录运行。后台常驻启动应隐藏窗口并保留日志；重复启动由独占锁拒绝。它与正式开机服务、站外监控分开验收。

无需更改旧管理器环境或业务账号即可显式配置 `.ops/local-monitor-binding.json`，严格格式见共享契约“本机监控显式绑定”。此文件含独立只读监控秘密，禁止查看/复制到交付报告、静态目录或Git；Windows ACL限当前运行账号和SYSTEM。API与监控均校验项目、既有库、回环端口，显式环境凭据冲突会拒绝。监控使用 `localBinding:true`，沿用每60秒、3失败建故障、2成功恢复及60秒启动宽限；未配置真实渠道只记录本机事件，禁止将其描述为真实通知送达。

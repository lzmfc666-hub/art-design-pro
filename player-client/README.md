# 独立打手端前端 1.0

这是独立 Vue 3 前端工程，拥有自己的入口、路由、状态、依赖、锁文件、样式、PWA 和构建产物。它不导入管理后台的 `src` 或组件，可将本目录单独复制到另一个仓库开发和构建。

本工程只负责打手网页，业务通过接口连接现有后台服务；不会创建另一套账号、数据库或资金账本。接口数据类型为本工程的兼容快照，变更时与后台共享接口契约核对。

## 公告与流动板报

在管理后台进入 **系统管理 → 打手端内容管理**，分别维护滚动公告和图片轮播。新增内容后可以保存草稿、查看手机预览、设置排序与北京时间展示区间，再点击发布。编辑已发布内容只保存草稿时，打手端仍展示原发布版；重新发布才替换。下架后停止展示，草稿和最近发布版保留，可再编辑或删除。该入口需要配置管理权限。

公告支持标题、300 字内滚动文字和详细正文；轮播支持 JPG/PNG/WebP 图片（最大 8 MB）和详细正文，建议上传横向图片。正文为纯文本，支持换行。排序数字小的在前，开始或结束留空分别表示发布后立即展示或长期展示。所有编辑、发布、下架和删除均记录到后台操作日志。

打手端大厅展示当前有效内容，点击可查看详情；轮播支持暂停、切换和滑动。在线时约每 15 秒更新，重新进入大厅或恢复网络后立即读取；修改内容无需重新部署。没有发布内容时隐藏整个公告/板报区域。图片和私有业务凭证分开授权，不能将私人收款码用作板报。

## 三个入口

| 服务             | 本机地址                               |
| ---------------- | -------------------------------------- |
| 管理后台页面     | `http://127.0.0.1:3006/#/auth/login`   |
| 现有后台业务接口 | `http://127.0.0.1:3007/api/studio`     |
| 独立打手端页面   | `http://127.0.0.1:3008/#/player/login` |

账号由管理后台创建。两端分别保存 HttpOnly Cookie 会话，同一浏览器可以同时登录管理员和打手，分别退出。旧嵌入页面的手机登录不会自动变成独立打手会话，第一次进入新端需重新登录。

## 本目录单独运行

```powershell
pnpm install --frozen-lockfile
pnpm dev
pnpm typecheck
pnpm build
pnpm preview
```

启动打手端前，现有后台接口服务需要已运行。开发默认代理到 `http://127.0.0.1:3007`。可以复制 `.env.example` 为本地 `.env.local`，设置：

```dotenv
STUDIO_API_TARGET=http://127.0.0.1:3007
VITE_ADMIN_URL="http://127.0.0.1:3006/#/auth/login"
```

`STUDIO_API_TARGET` 是后台服务的源地址，不带 `/api/studio`；`VITE_ADMIN_URL` 是外部管理后台入口。网页向自身的 `/api/studio/*` 发请求，代理统一连接后台端口，因此 Cookie、图片和收款码不用直接跨域。Vite 的开发/预览代理自动增加 `X-Studio-Client: player`，只转发 `studio_player_session`，不会把后台管理员 Cookie 发送出去。

在父项目中也可用 `pnpm dev:player`、`pnpm build:player`、`pnpm typecheck:player`。父项目的 `pnpm dev` 会启动三个独立进程，打手端并未嵌入后台页面；也可以仅运行 `pnpm dev:api` 和 `pnpm dev:player`。

## 单独发布

构建产物仅在本目录 `dist/`，与管理后台根目录的 `dist/` 分开。可以单独更新和回滚打手端静态包，同时后台继续使用原服务和数据库。

部署到单独站点，例如 `player.example.com`，静态根目录使用本目录的 `dist`，将 `/api/studio/` 代理到现有后台端口。代理须强制设置 `X-Studio-Client: player` 并只转发 `studio_player_session`；保留后端 `Set-Cookie`、`X-Studio-User` 和 `Cache-Control: no-store`。正式前端 Origin 加入后端 `STUDIO_ALLOWED_ORIGINS`，HTTPS 下后端设置 `STUDIO_SECURE_COOKIE=true`。后台构建时 `VITE_PLAYER_CLIENT_URL` 指向独立打手站点，以便旧手机书签跳转。

父项目提供简易独立静态代理服务：先构建后运行 `pnpm start:player`，默认监听 3008，读取同名 `STUDIO_API_TARGET`。该代理只有静态资源和固定接口转发，没有业务数据库。正式环境仍需 HTTPS、持久后端、备份及设备验收。

Service Worker 不缓存 API、附件或资金写入。关闭网页后的推送仍受服务器配置、系统版本、添加桌面、授权和网络影响，必须在真实安卓/iPhone 上验证。接口权限、资金校验和会话撤销始终由后端执行。

## 联调中额外修复

- 财务页从订单页切入时重新读取完整授权数据，避免沿用精简快照，造成新退款不显示、订单号变编号、退款选单为空。

- 退款驳回重新通知；关闭问题、存单、全退和重新指派会使过时通知及操作目标失效。
- 待办退单计数排除退款或存单暂停项，历史申请仍保留。

## 回退边界与验证

Git 回退恢复代码，不能恢复或抵消订单、资金和图片的后续变化。修复前标签始终保留，但旧 `ba7b1b9` 不理解存单和退款暂停，不能直接处理引入新规则后的现用库。

- 切换任何回退版本前，先用本轮检查器对“当前库 + 回退版本的可信发布清单”执行同样的只读检查。缺 `refund-execution-v1`、`stored-orders-v1`、`problem-orders-v1`、`problem-staff-only-v1` 等必要能力会退出 1；输入无效退出 2。均不得继续启动目标版本。有问题记录时旧 RC1 缺少客服处理保护，也会被拒绝。
- 本轮是首次引入这些语义，不能声称修复前标签本身已是兼容回退版本。本轮经验证的候选包和完整清单应离线保留，作为后续兼容版本的回退基线；它继续识别当前存单并执行退款、存单拦截。
- 若本轮更新后需要撤除某个界面或图片功能，使用保留上述服务端拦截的兼容补丁；不能为了撤界面把整个程序退到旧规则。没有可用兼容程序时保持维护，保留当前库，先修程序。
- 备份恢复已在新离线路径验证，未覆盖源库。正式运行后有新订单或交易时，旧备份绝不能被当作普通代码回退使用；需要恢复数据应先保护当前库，明确核对恢复点后的交易及图片影响，再由用户决定。

原程序目录、旧代码标签和备份应留存；更新包、业务备份和真实密钥分别存放，业务备份不能上传到公开 Git 仓库。

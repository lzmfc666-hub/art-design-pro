## 配置、兼容与接口

后台保存字段为 `AppearanceConfig.playerOrderCardImage:Attachment|null`，附件为 `{id,name,mime,size,url}`。一张图用于全部订单卡片；未配置、明确移除或恢复默认为 `null`，后续打手显示原游戏图标。

上传、预览、替换和移除先修改草稿，使用原“保存到工作室”按钮后生效；“读取已保存设置”重新核对当前版本。整套“恢复工作室默认外观”会清空卡图并恢复其他原外观默认值。上传和预览不自动发布配置，也不产生测试通知。

旧配置缺字段时只读补 `null`，不改写历史配置。旧保存请求省略字段时保留当前卡图；明确提交 `null` 才表示移除。保存和恢复沿用 `{config,revision}` / `{revision}`、事务内权限/会话核验及审计，旧 revision 返回 409，保留草稿并由用户读取最新后确认。卡图新增、替换、清空仅允许具有 `settings.manage` 的非打手账号；打手即使有该权限覆盖也不能改变卡图。原不改变该槽的其他外观行为保留。

所有接口前缀为 `/api/studio`：

| 读取 | 契约 |
| --- | --- |
| GET `/appearance` | 原后台完整外观增加 `playerOrderCardImage`。 |
| GET `/player/appearance` | 当前启用且允许登录的打手返回 `{revision:number,orderCardImage:Attachment|null}`；只投影这两个字段，不返回后台配置、修改人或业务私有信息。 |
| GET `/player/changes` | 增加 `appearanceRevision:number`，与全局外观 revision 一致；继续使用原 `version/changed`。 |
| GET `/uploads/:id` | 原认证图片下载，按当前配置、所有权及其他独立授权重新裁决。 |

JSON 响应为 `Cache-Control:no-store`，认证图片为 `private,no-store`。非打手读取新接口返回 403；无、过期、撤销或关闭登录会话按 HTTP 认证返回 401，服务层也拒绝停用或关闭登录的打手。

后续客户端应复用现有 scheduler/store，在首次进入大厅或任务、恢复网络、页面可见及摘要 `appearanceRevision` 改变时重读。保持现有约 15 秒摘要节奏，不新增逐卡片轮询，不以 Logo、轮播或私图替代；无图、读取/加载失败、退出或换号时清旧图并降级，不存入业务持久缓存或 Service Worker。`appearanceRevision` 不参与任何订单或资金写入校验。

## 图片权限与安全复查

图片继续通过真实上传接口，接受 PNG/JPEG/WebP、匹配签名及不超过 8MiB 的附件；拒绝外链、data URL、SVG及伪造元数据。新图片属于当前配置人；其他管理员只能复用当前保存配置中的合法图，历史配置本身不授予复用权。

卡图用途检查拒绝当前配置人自己或他人的私人收款码、客户/资金/退款/提现/费用凭证、订单材料及敏感历史引用。检查权威业务状态、私人标记、资金实体、冷热业务审计和成功操作结果中的 `receipt/qrCode/screenshots` 等结构化附件字段。文件名、普通说明文本和卡图本身的外观审计不会被误判为私人用途。

复查曾发现：通用资金请求记录会保留未实际采用的附加 `receipt`。打手可在合法提现请求中附带公开卡图 ID，若把原始请求参数当已登记私人用途，后续管理员合法保存原图会被错误拒绝。现改为读取权威状态、结果及业务审计，金融成功记录只检查 `result_json`；专项已验证额外参数不污染分类，管理员仍可合法保存原图。实际私人凭证及其历史引用继续拒绝共享。

反向保护位于统一附件入口，在所有权放行之前执行：当前卡图不能随后转作业务凭证或私人资料。共享下载权不扩展为金融/订单附件复用资格。

替换、移除或恢复默认后，旧图不能仅凭旧卡图或审计继续共享。原上传人、其他当前合法外观槽及业务权限独立判断；同图仍在公开 Logo/登录槽时，其原公开授权保留。卡图不会加入匿名 `/appearance/public` 或 `/public-assets` 的新授权。GC 沿用当前状态和审计引用保护，保留旧二进制不恢复旧共享权。

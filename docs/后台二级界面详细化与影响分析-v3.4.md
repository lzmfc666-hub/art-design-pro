日期：2026-10-15。状态：本轮本机收尾与联合验收完成。长详情及长编辑/审批表单已改为独立页面，短末次确认保留；既有资金、权限、订单保护及独立打手业务源码保留。下文给出真实浏览器、回归、构建、磁盘压力和离线恢复结果；真实手机与正式上线场景仍未验证。

## 本轮范围及交互方向

用户要求真实业务的详情及操作表单详细化，并补充“界面太大了，还要下滑，下滑的直接做跳转”。当前长详情、长表单采用 `BusinessDetailPanel` 的独立业务详情页：保留当前菜单及侧栏，正文按摘要、已有明细和操作口径分区，操作栏固定在详情页底部。短的末次确认仍使用原确认框，补充当前对象及已有金额、日期、状态等上下文。

独立页使用当前业务路由中的 `secondary` / `secondaryRecord` 作为页面栈。URL 仅记录稳定界面键及公开记录标识，不保存表单正文、客户信息、凭证、资金请求体、Cookie 或操作编号。打开、返回及刷新仍经过现有页面与接口权限；URL 中出现记录编号不能授予读取或操作权限。

公共展示组件包括 `BusinessDetailHeader`、`BusinessDetailSummary`、`BusinessDetailSection`；`businessConfirmMessage` 只生成确认框展示内容，不请求数据或改变提交行为。模板、组件演示、嵌套菜单示例不属于已确认的真实业务范围。

## 刷新、后退及失效边界

- 只读记录恢复使用当前账号的授权快照、原详情 GET 或原初始化方法。记录不存在、当前角色无权读取、状态已结束时显示具体返回说明，不凭旧 URL 打开空表单或恢复操作权。
- 表单刷新只重新初始化当前合法记录；未保存输入不写入 URL、浏览器持久存储或后台草稿。新表单也调用原准备方法，不直接设置可见状态跳过初始化。
- 工资月份恢复先通过原月份读取取得相符的核算结果；读取失败不将其他月份明细冒用为原记录。
- 内容编辑与嵌套预览恢复会说明“当前已保存草稿”及未保存编辑丢失。路由的父子栈保留原 `closeEditor` 确认；跨模块跳转不会同时弹出两份同类丢弃确认，取消保留原输入和详情 URL。
- 临时报表行使用原模块、生成时点和索引绑定。整页刷新无法核对原筛选、字段及生成时点时，明确提示原预览已失效，要求返回重新预览；不把相同索引指向重新生成的另一行。
- 详情中的跨模块链接先正常进行原授权路由跳转，由详情载体协商关闭。不能先清详情 model 再发起另一跳转，造成路由竞争。
- 结果未知的操作仍遵循原完整 body / 原 Actor / 原编号机制。新载体不自动补发，不把没有原完整 body 的恢复标记解锁成新请求。
- 工资、经营报表和个人中心从其他模块首次进入或再次激活时，使用原月份读取取得完整当前授权核算。个人中心显式 `includeReports=true`，服务端仍裁决本人/全员范围，不把先前模块的空报表当成零收入或完整工资。没有新增定时轮询。
- 后台订单操作页的未知结果仍使用既有内存意图及“刷新订单并重新确认操作”方式；本轮只是将原按钮保留在独立操作页上，并让原返回处理拒绝丢弃未知意图。它不是独立打手端的原结果GET恢复机制，不能混称为相同持久恢复证据。

## 资金、权限与独立打手端的影响

### 发现的具体问题与局部修复

- 长页面载体协商关闭时，15个原单向model调用方只在close事件后清理，导致正常返回无法确认；改为原update回调先确认关闭，提交函数不变。成功操作后正在刷新的同一父详情可以保留并接收子页返回，忙页换记录/离开仍拒绝。
- 旧订单`?id=`链接在同一订单再次跳转时可能关闭后不再读取；换记录时旧closed回调又可能消费新model。旧链接先规范为公开详情URL，记录切换在原closed后调用原初始化；内部返回不残留旧id并重新打开。
- 原hash路由离开确认可能被Element Plus默认hashchange监听意外关闭，确认Promise无法完成。内容、建单及外观的原离开确认明确保留到用户选择，不增加第二个确认或放宽忙锁。
- 报表读取缺口使工资页面首次从其他模块进入时缺完整核算；经营报表和个人中心也可能沿用未请求报表的空快照。补原授权GET及正确includeReports参数，不重算历史资金或扩大服务端投影。
- 员工权限撤回后的编辑页及客户流水403后的旧缓存仍可能显示私人表单/资料。撤权或原读取/提交403后清空相应缓存、密码及写入入口；保留原业务提交保护。
- 原全局样式覆盖详情间距、个别模板换行事件及遗留关闭标签造成展示/编译问题，已局部修复。没有批量格式化无关文件。

测试工具问题单独记录：联合脚本模拟时钟与真实浏览器付款时间跨日，已填隔离时钟下的真实允许日期；新增摘要使原泛化文字定位重复，改为对应对象的准确范围。隐藏checkbox用实际可见标签勾选并断言选中；字段读取等待原表单挂载；窄屏ElTabs只通过原可见滚动箭头后正常点击，未使用强制点击或放宽disabled。两份旧打手并发测试仍找`.p-order-no`，当前交付卡片已使用公开`.p-order-number-value`：仅在QA目录生成定位适配副本，全部原断言逐字保留，并记录原/副本SHA及反向还原一致性；原文件和打手工程不改。所有失败/中断证据保留，不能计为最终通过。

本轮展示及载体调整不修改 `useFinanceActions.ts` 的资金提交、原 mutation body、requestId、revision、后端账户权限或历史资金记录。金额摘要来自原完整授权汇总；当前页分页只影响明细阅读，不能用于推算完整钱包余额、工资、提成或利润。私人图片沿用原认证读取及权限，内部备注、客户私人信息不进入新 URL。

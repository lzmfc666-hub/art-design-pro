## 检查与发布对应

在项目目录执行 `pnpm ops:check`。这是只读检查，默认示例指向本机；返回PASS/WARN/FAIL及安全处理代码，正式参数/证据缺失会返回非零，不能当作脚本异常后忽略。检查覆盖源码和两端全部构建、HTTP部署资产、接口发布、域名/HTTPS/Origin/Cookie/代理/端口、持久库与环境隔离、角色及示例账号/工资方案/项目配置、磁盘/日志、备份/异机/恢复、服务和监控启用证据。不会登录真实账号、读环境秘密、清测试数据、改账号或金额。

构建两端后 `pnpm ops:release`，在私有`.data/releases/current.json`记录源码及两端全部文件的摘要。只生成对应关系，不发布、不证明常驻服务已经升级。修改源码/契约/脚本或任何构建文件后旧清单失效。API启动核对有效清单；缺失则release:null。正式机器再核对HTTP资产和health返回值；只读静态200、匿名session或Git提交号都不能证明最新业务就绪。

把`deploy/ops.example.json`复制到私有配置目录，再根据实际环境填写，不能把示例的关闭值改成“已经上线”证明。四维分别是code、configuration、enabled、verified；`studio-ops-evidence-v1`证据还须同环境/同发布、最近24小时、非模拟，所需字段在检查器中验证。普通配置声明不证明Secure Cookie、CORS、代理来源或防火墙实际生效，service证据须有deploymentSecurityVerified。证据JSON是运维核对记录，不是防篡改的外部认证。

## 两层监控与独立告警

API新增公开GET `/api/studio/health/live`与`/health/ready`。live只证明进程响应；ready先核对API连接、再由工作线程只读检查状态和必要表，默认总等待1.5秒、锁等待150毫秒、合并并发及1秒短缓存。失败503只给最小状态，不泄露表名、路径、身份和记录。默认本机回环绑定；正式仅由HTTPS反向代理公开必要路径，3007及管理/控制端口不得直接外网开放。

独立随机`STUDIO_MONITOR_TOKEN`仅允许GET `/ops/summary`及明确时间窗内的`/ops/diagnostics-summary`；不使用管理员密码/Cookie，不能写入、读私人对象或访问业务接口。API与本机监控需要同一只读秘密，均从受限环境注入，禁止粘到日志/命令参数/仓库。诊断默认关闭；如需启用，API设置`STUDIO_DIAGNOSTIC_HOURS_UTC`（逗号分隔0–23），监控配置对应UTC窗口及间隔。例18UTC是次日北京时间02时，不凭服务器本地时区猜测。

启动 `node scripts/studio-monitor.mjs --config 私有配置.json`；一次采样加`--once`；只读查询加`--status`；停用自身守护加`--stop`。OS锁、项目归属和随机控制标记验证身份，重复启动/未知端口只拒绝，状态文件本身不证明进程存活。停用命令不按PID或node名称批量终止其他服务。控制只在回环端口，默认3011，私有目录不可位于网站静态目录（包括链接别名）。

默认60秒、连续3次失败形成故障、2次成功恢复、启动宽限60秒；维护窗口不探测、不假装恢复。监控响应时间、5xx差量、内存、磁盘/WAL、日志、推送积压、备份/复制、监管心跳及预算。401/403/409/429单独计数；监控身份401/403作为凭据故障，正常业务授权/冲突/限流不计服务器5xx。没有采样为unknown，不沿用旧“正常”。低峰诊断明确异常一次报警，仍只读；诊断失败也受最小尝试间隔约束。

默认警戒示例：RSS1GiB、请求P95 1.5秒（至少20样本）、5xx超过5%（至少20新请求）、磁盘少于1GiB、WAL256MiB、数据库审计日志450MiB、推送到期积压5分钟、备份2小时、异机24小时、证书21天。阈值须依正式磁盘/RPO和负载重设，不代表容量承诺。业务子服务输出及管理事件文件默认8MiB封顶、90%告警，满后保留文件并消费后续输出以免阻塞业务；后续日志可能丢弃，需运维归档后恢复。原生Job/bootstrap文件仍需容量探测和人工归档，不宣称全部日志自动轮转。

守护、备份与监控共用`STUDIO_OPS_DIRECTORY/events.sqlite`（配置storage.opsDir须同目录、同environment）。事件及去重状态不在业务事务中；最多1000故障、5000事件、5000投递，完成历史30天，活动/待发不悄悄删除，满时明确计数。状态未变不重复发，恢复一次；独立投递默认3次、10秒超时、30秒起至5分钟有限退避，失败不冒充接受，也不阻塞业务。接收方应按固定deliveryId去重，网络响应丢失时不承诺严格一次。消息仅含环境、服务、时间、类别和排查代码，没有客户/金额/凭证/秘密URL或堆栈。

真实告警须有已授权渠道配置`alerts.authorized:true`、HTTPS目标的环境变量，并明确加`--enable-authorized-delivery`。默认disabled；不会自动把启用前的旧disabled事件补发。告警失败有独立本地状态和抑制递归事件，需另一个外部渠道/平台观察；同一个失效渠道不能保证送达其自身失败告警。本轮仅本地模拟接收，未发送实际消息。

旧`STUDIO_BACKUP_FAILURE_WEBHOOK`直接提醒保留兼容。正式改用统一故障队列时，应在明确配置中停用旧直接提醒，避免同一接收器同时走两条已启用通道而双发；统一队列的去重不能替代旧直发的迁移核对。本轮未读取或更改已有外发秘密配置。

站外用`deploy/ops.external.example.json`在独立机器/平台部署同一探测器，填写正式HTTPS四个公开目标、发布ID、两个index.html的SHA。外部最小探测无需业务身份；两端页面核对app内容及可选完整index指纹，接口核对JSON/发布/DB-ready，拒绝跳转、伪200和无效证书，检测证书到期。独立主机、网络、渠道和实际证据未提供前，站外监控未启用。本机external模式测试不覆盖整机断电/外网中断。

站外示例的`.ops-external`只是待替换路径；正式请选择仓库外的绝对私有目录，或已排除的`ops-private/external`，并核对Git状态及NTFS权限，不能把运维库/控制标记加入版本库。站外探测机不需要复制业务数据库、浏览器会话或生产推送私钥。

## Windows服务与恢复边界

复用`pnpm local`，新启动通过guardian→manager→单个服务逐级归属管理；每级只管理自己创建的进程/原生Job，API明确活但DB失败不重启。默认本机启动宽限30秒、5秒探测、连续3次失败、5秒冷却、有限指数退避，服务60秒最多5次恢复。主守护的预算窗口120秒。正常退出优先，超时只结束自己的句柄家族，不扫描/接管旧PID。

实际部署确认后，在对应运行账号执行以下动作，统一使用`-TaskName Studio-Production -RuntimeDirectory 私有运行目录 -NodePath 绝对node.exe路径`：

```powershell
powershell -NoProfile -File .\scripts\studio-service-windows.ps1 -Action Install <相同的明确参数>
powershell -NoProfile -File .\scripts\studio-service-windows.ps1 -Action Status <相同的明确参数>
powershell -NoProfile -File .\scripts\studio-service-windows.ps1 -Action Start <相同的明确参数>
powershell -NoProfile -File .\scripts\studio-service-windows.ps1 -Action Stop <相同的明确参数>
powershell -NoProfile -File .\scripts\studio-service-windows.ps1 -Action Uninstall <相同的明确参数>
```

以上是参数说明，不应照抄尖括号占位符。Install登记当前账号S4U、受限任务、绝对Node和受限运行目录ACL；不覆盖已有任务。开机与每分钟触发同一个宿主，MultipleInstances忽略重复。宿主内部有限恢复guardian；每分钟触发用作宿主退出后的恢复，绕开本机未验证成功的TaskScheduler RestartOnFailure。预算耗尽/配置阻断会写`guardian-recovery-blocked.json`，周期触发不再启动子进程；明确Start清阻断标记并启用触发，需先排查原因。Stop先Disable任务，不会下一分钟自动复活；Uninstall保留日志。

S4U不具备自动访问远程共享的凭据，不能拿本机任务成功冒充正式UNC复制可用。正式服务账户、NTFS业务库/备份/运维目录ACL、代理环境和网络存储身份仍需按目标服务器核对。旧版已常驻manager并未因源码保存自动升级；升级需维护窗口、确认旧归属后停写并退出旧实例，再启动新guardian，禁止让两个管理者竞争同一API。不要为验证开机重启用户电脑；真实boot、整机断电恢复仍需正式条件演练。

## 备份、异机和恢复

现有SQLite一致性备份使用SQLite backup API，包含WAL已提交内容，绝不能只复制在线主文件。默认计划关闭；`STUDIO_BACKUP_INTERVAL_MINUTES`、`STUDIO_BACKUP_RETENTION_COUNT`、`STUDIO_BACKUP_DIR`明确配置后才有定时。例每60分钟保留24份只覆盖约23小时成功恢复点跨度，并非必然24小时；失败/停机/任务耗时都会改变实际覆盖。周期须由允许丢失时间和容量决定，本轮不替用户决定正式RPO，不启用生产清理。

检查器的`nominalCoverageHours`是“份数×周期”的名义分段窗口，并标明假定连续成功；它不是最早至最晚恢复点的实测跨度。实际跨度必须看真实完成清单的首尾时间与缺口。本轮业务计划关闭，实际历史覆盖未知，不以示例份数冒充已保留的天数。

备份清单有开始/完成时间、complete、schema、应用发布或null、字节、SHA和私人数据标记。未完成/损坏不替换最近成功；目录跨实例锁避免重叠，过期锁保守跳过待人核对。清理只针对本工具管理且源库匹配的完成文件，核对绝对边界与链接；其他文件、旧人工备份不动。源库、备份、ops、日志和配置不进静态目录/Git，正式ACL仅服务账号/恢复管理员，私有资料不能当公开交付附件。

异机复用`server/backup-replication.mjs`，当前内置仅接受核对host/share的真实UNC或受控adapter，先临时传输、核验SHA/大小再发布，不覆盖既有目标。普通本机目录只能simulation。复制默认关闭；需要在明确服务配置的backups.replication传`enabled/kind/targetId/remoteIdentity/directory`（adapter方案另审接入），现有CLI不自动识别陌生远端。每次本地成功、异机失败独立记录/告警。异机目录实际容量、ACL、连接身份及故障演练未确认前不能写“异机完成”。本地另一盘也不等于异机。

CLI显式接入可设置`STUDIO_BACKUP_REPLICATION_CONFIG`为私有JSON绝对路径，字段参考`deploy/backup-replication.example.json`；示例enabled:false，`.invalid`主机不可当真实目标。只有明确生产CLI维护环境才读取该文件，显式测试库默认忽略。超过32KiB、畸形、静态目录/链接中的配置在开业务库前拒绝，不输出配置正文。正式远端身份及目录未授权前不启用。

重复演练执行 `node scripts/studio-ops-recovery-drill.mjs --final`，只生成新隔离库，不接受正式数据库路径；完整schema/21表/BLOB/SHA、资金和权限、幂等、旧会话/订阅/待发和租约核对，源库备份后新交易独立验证。旧备份没有SHA明确unknown，不以完整性ok替代来源校验；已完成快照存在非空WAL、超出schema2或复制时源变化会拒绝恢复。演练耗时只是本机小库测量，不是生产RTO或零数据丢失承诺。

正式恢复只能在明确授权后人工切换：

1. 宣布维护，停止入口写入；停止且确认唯一生产推送发送器、维护、计划备份/告警外发，保存最后事务时间及当前源码/构建/配置版本。

   必须先停用开机/周期触发并停止父守护/监管器，不能只结束API子进程，否则自动恢复可能重新启动旧发送器。Windows使用已确认归属任务的Stop操作并核对任务Disabled、家族进程退出；未知或旧协议实例先核对项目、身份和控制方式，不按名称批量终止。
2. 保留最新原库完整SQLite快照及独立备份，不覆盖或删除源库/WAL。确认恢复点、之后可能丢失的新交易范围，由业务负责人核对。
3. 验证来源、SHA、schema、应用兼容和完整性，恢复到新私有离线目录。恢复环境不继承真实密钥/渠道，关闭自动扫描、维护和发送。
4. 核对订单、钱包、储值、押金、提现、工资、资金流水、BLOB、审计、消息、幂等和配置；核对分账、余额及授权。不能把过期接口成功当作当前权限。
5. 原会话在备份时仍可能有效，正式切换应撤销全部旧会话；本轮默认切换方案同时撤销推送订阅、取消旧待发/处理中任务并清除租约，用户重新登录/主动绑定。不要只清lease就重发历史通知。演练仅在policy副本操作，未修改正式记录。
6. 再确认原发送器确已停止，再启动唯一新实例；核对HTTPS/Origin/Cookie/代理、只读就绪、角色及真实金额对账，授权后重新开放，保留回退点和完整记录。
7. 失败则继续停写，停止恢复实例/发送器，保留失败副本，重新核对未被覆盖的最新原库。已经开放产生新交易后不能简单回退旧快照，必须重新核账与决策，禁止自动合并/改账。

没有远程恢复/命令执行接口。本轮不覆盖正式数据，不同时运行源库和恢复库的生产发送器。

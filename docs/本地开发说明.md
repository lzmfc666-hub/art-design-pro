# 金盾电竞工作室后台

直接改造 Art Design Pro 原源码：原工作台显示订单及经营数据，原用户、角色、菜单与个人中心管理真实账号；订单、财务、配置和考勤使用源码自带的表格、搜索栏、图表及表单。全站共用原 App、动态路由、Pinia、布局和主题，配套本地 Node.js API 与 SQLite 数据库。后台先开发，独立打手端后续接入，双方准备完成后再共同上线。

## 本地运行

需要 Node.js 24+、pnpm 11+。在项目目录运行：

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

浏览器访问 `http://127.0.0.1:3006`。前端端口 3006，后端端口 3007，默认只监听本机。

初始超级管理员账号为 `admin`。首次启动会随机生成初始密码，保存在 `.data/bootstrap-password.txt`。也可以在首次启动前用环境变量 `STUDIO_ADMIN_PASSWORD` 自行指定初始密码。该文件、数据库、上传图片、会话均不提交到 Git；不要将 `.data` 上传到公开仓库。

超级管理员在“系统管理 → 人员管理”中新建员工及打手账号、设置密码和角色。超级管理员始终拥有全部权限；普通管理员默认不开放财务、利润及全员工资，不能创建、修改或重置超级管理员账号。其他账号遵循角色默认权限，可逐人覆盖。旧版初始 admin 账号自动迁移成超级管理员，原订单、密码和会话保留。

原框架的菜单布局、主题色、深浅主题、多标签页、搜索、锁屏及组件页面继续保留。原工作台及系统管理已接入真实业务接口；超级管理员还可访问模板中心、组件中心与功能示例，示例页单独标注。页面底部 Vue 开发工具仅登录后的超级管理员可见；原权限切换示例仅在页面内预览，避免覆盖真实登录。

业务总览提供岗位常用入口与真实待办；顶栏通知可查看订单动态和处理结果。全局搜索（Ctrl + K）按菜单、订单、客户和人员分开，再选择具体搜索字段；业务列表也按各字段独立筛选。订单支持状态与日期筛选、详情地址同步及复制订单号；同一页面切换财务等标签、筛选或打开详情保留滚动位置，进入其他页面才回到顶部。下单尚未发布时，离开页面会提示保留当前填写内容。保存或上传期间相关弹窗与详情禁止关闭。

主页参考所提供的蓝色工作台截图，提供今天、近 7 天、近 30 天和自定义日期。营业额、订单、客户消费、利润、人员新增、打手待付、接单和费用按实际权限展示，卡片可查看口径详情；工资及考勤补充卡只显示本人已有权限数据。截图中的储值、存单、押金已按用户选择用现有业务替换，没有新增相关收费或余额流程。主页可把所选日期带入明细导出。

营业额为收款未扣退款，净收入扣实际退款；区间利润沿原付款日归属且不摊月度底薪，完整月份才提供扣底薪利润。没有旧建档日期时新增人数保持未知；钱包卡是当前余额快照。增长率仅在上期有有效非零数据时计算。更改主页日期不改订单状态、工资月份或业务结算结果。

## 界面外观

在“系统管理 → 界面外观”设置工作室名称与 Logo、业务页面背景、主页欢迎横幅和菜单 / 快捷入口图标，也可编辑登录页标题、副标题、介绍文字及图片背景。Logo 同时作为浏览器标签图标；背景可选择原默认、纯色或上传图片，图片支持 PNG、JPG、WebP，最大 8MB。背景图可调整遮罩，横幅可隐藏原玻璃装饰，菜单图标从预设中选择。全局毛玻璃开关作用于页面卡片、搜索栏、布局和弹出界面，兼容深浅主题与手机菜单。

小预览随编辑更新，“预览应用”仅临时影响当前窗口；“保存到工作室”后其他成员刷新页面即可使用。只有具有业务配置权限（`settings.manage`）的账号可以编辑、保存和恢复默认，操作会记入日志。多人编辑冲突时保留草稿，先读取最新设置，再明确确认替换。恢复默认保留历史上传图片。

外观设置不改订单、工资、退款或权限规则。原框架模板及组件示例继续保留原页面背景；个人深浅主题、主题色与布局偏好仍由原设置管理。未登录访客只可读取当前保存的登录外观和公开品牌图片；其他背景及业务凭证仍按原权限控制，共享品牌图片不能代替其他人的业务凭证。

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm start
```

`pnpm start` 运行后端并提供已构建的 `dist` 页面。正式部署另行配置服务域名、HTTPS、数据备份和运行管理，本次不发布到公网。

## 使用顺序

1. 系统管理 → 业务配置：维护订单项目、客户价格、整单打手报酬、任意来源平台与各平台店铺、等级等待时间；每个来源独立设置是否要求店铺、平台订单号、付款凭证和是否允许落地付。
2. 系统管理 → 人员管理、角色与权限：建立员工及打手，设置等级、接单上限与权限；订单业务 → 客户档案维护客户名称和来源。闲鱼默认要求平台订单号，客户可新增多个编号并分页查看，不设业务数量上限；其他来源按管理员规则处理。档案编号只登记关联信息，不生成订单或营业额。
3. 订单业务 → 创建与派单：选择项目，补客户、来源、房间码或游戏 ID、备注和付款信息，再发布到抢单池或指派。付款凭证可以拖入图片上传；已移除沟通渠道输入，历史记录仍保留。
4. 打手通过预留接口接单并提交完成截图。后台不增加客服代接单或代上报功能。
5. 财务管理 → 验收与结算、工资与提成：验收、退款、提现审核及人工发放登记、打手扣款与补款、费用、工资方案与工资月结。不参与运营提成的来源在工资方案内填写比例 0；未填仍是待配置，游戏大厅保持原固定 0 规则。
6. 工作台 → 业务总览、经营报表核对经营数据；系统管理 → 操作日志查看修改前后记录。

## 数据报表导出

在“数据报表 → 自选导出”选择模块、字段与范围；各业务页的“导出本模块”可直接带入对应模块。支持订单与接单/上报历史、客户、退款、提现与余额、费用、工资核算与发放快照、工资方案、考勤、人员及权限、业务配置、界面外观配置、经营报表、日志与本人资料。

所有模块可选择日报、周报、月报或总计报表。日报按所选日，周报按周一至周日自然周，月报按自然月，总计涵盖已有历史；还可按明细日期、人员、平台、状态和具体搜索字段筛选。订单日期可按创建、客户付款或完成时间选择。人员、配置和余额是当前快照，不能还原历史配置或历史余额；部分日期区间不摊月底薪，工资核算保留原核算月，发放记录按实际发放日期。具体口径在字段区域注明。预览每表前 20 条，下载包含所选范围内全部记录，最多合计 100,000 条；超过时需缩小范围。

多个模块导出为同一 Excel 的不同工作表，每表可独立勾选字段。金额导出为元数值，比例为百分数值，缺配置保留“待配置”；长订单号、游戏 ID 与前导零作为文本。没有记录的模块仍导出所选表头。凭证只导出名称和站内地址，查看图片仍需登录及原记录权限。

目录、预览和每次下载由服务器重新核验 `reports.export` 及各模块权限。客服与客服主管禁止所有数据导出，个人权限覆盖也不能放行；只有本人权限的其他员工只导出本人数据。审计日志导出全量可见记录，不受页面列表条数限制，可选热日志、归档日志或全部。Excel 导出遵循权限脱敏，不能用作完整日志恢复备份。密码、密码哈希与会话不导出。

## 重要业务口径

- 所有金额以整数分保存，提成比例用万分比；平台订单号按文本保存。
- 客户实际付款日、订单完成月份、退款实际发生时间分别记录。经营收入、退款和相关订单成本回归原付款日，工资提成按完成月份归属。
- 财务验收前的打手报酬为约定 / 预计成本；验收通过才形成可提现报酬。提现发放不再次扣经营成本。
- 订单取消与实际退款分别处理；有执行历史的取消订单保留约定成本，直到财务确认补偿。
- 客服与客服主管默认只看本人业绩，不开放工资和任何数据导出。利润、工资、接口返回与日志均按权限限制。
- 审计前后值按实体和查看权限脱敏，报表导出沿用相同结果。全员工资发放须同时有工资管理及全员工资查看权限，只有本人查看范围的账号不能批量发放。
- 底薪及提成比例缺失时显示“待配置 / 统计不完整”，不静默按零结算。
- 已提现后退款涉及的打手报酬差额由财务人工确认并登记处理结果，不自动扣减打手后续收入。
- 当前工时不参与工资计算；工资按工时计薪和迟到缺勤扣款尚未开放。
- 考勤默认显示在职人员“正常上班”，这是界面默认值，不自动生成记录或累计工时。有休息直接编辑，实际工时单独登记；修改班次或备注保留人工工时，休息工时为 0，未来日期不能提前登记实际工时。旧排班记录保留。
- 财务、店长、老板、超级管理员且具备订单编辑权限时可更正订单状态，普通管理员不包含。更正必须填写原因，执行、验收及完成状态校验负责人、完成凭证和收款；打手报酬与佣金同步冲销 / 恢复，防止重复入账。已有工资结算的订单不能借状态更正替换原人员或金额，应走独立财务调整。
- 打手扣款和补款由具备提现处理权限的财务账号登记，必须填写原因。扣款只扣当前可用余额，超过部分登记待追回差额，由财务填写线下追回或免除结果；已发放与在途提现不直接改写，也不自动扣未来收入。

## 日志维护与接口现状

原源码“服务器监控”使用随机演示数据，没有真实健康检查、检修或自动修复接口。已提供的打手接口支持查看可接订单、接单、提交验收、查看钱包和申请提现；直接指派后仍待该打手接受，不能把指定负责人当作已经接单。

操作日志已迁移到 SQLite 独立索引表，按页查询。默认保留最近 90 天、最多 10,000 条热日志，较旧日志自动归档；归档容量默认上限 500MiB，达到 90% 提示维护。容量耗尽时阻止需要审计的业务写入并回滚，防止日志无界增长或业务成功却没有日志。

系统管理 → 操作日志提供容量查看、归档以及备份后清理。完整权限账号先下载选定日期以前的完整 JSON 归档备份，确认文件保存，再执行二次确认清理；服务器验证短时凭据与备份范围，范围变化须重新备份。普通日志 Excel 为脱敏报表，不能替代该备份；一般配置管理员不能读取完整备份或清理。

若日志已满，具备完整备份权限的账号仍可登录并进入日志维护页；普通业务写入继续阻断，维护登录另存最多 1,000 条、保留 30 天的安全记录，清理恢复后继续普通审计。部署时仍需定期备份整个数据库及保存下载的归档文件。

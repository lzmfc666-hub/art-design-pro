# 发布校验跨平台修正 RC8

日期：2026-10-18。本轮只修正发布工具，业务代码、两端页面产物字节及人员、订单、资金和图片均不改动。RC8 是包含此前修复的完整更新包，替代 RC7 用于接下来的发布准备。

## 原因与修正

用户在雨云 Linux 用 Node 24.22.0 解压 SHA-256 一致的 RC7 包后，发布校验返回 `verified:false`。原源码指纹对主机原生的绝对路径排序，再统一路径分隔符，导致 `src/router/routesAlias.ts` 和 `src/router/routes/` 的先后顺序在 Windows、Linux 不同；构建指纹还依赖默认语言区域排序。

新算法先统一成 `/` 分隔的相对路径，再按固定 UTF-16 字典序排序。文件内容继续逐个校验 SHA-256，清单自洽、缺失、额外文件和内容篡改均保持严格检查。旧清单可继续只读解析其原有摘要以作兼容性检查，但不能因此放过实际文件不符。源码及构建摘要会因规范顺序改变，因此生成全新 RC8 身份，不覆盖 RC7 包、标签或侧车清单。

## 验证范围

发布及打包回归 27 项通过（其中新增 17 项），覆盖路径分隔符、真实目录前缀反例、语言区域无关性及文件缺失／新增／篡改。备份、容量、恢复兼容、健康探针及监控相关回归另有 59 项通过，合计 86 项通过、0 失败、0 跳过。三个改动脚本／测试通过严格 ESLint 与语法检查。日志分别见 `rc8-release-regression.log`、`rc8-dependent-regression.log`、`rc8-lint.log`、`rc8-syntax.log`。

独立只读 POSIX 路径语义执行原 RC7 校验模块，复现全部逐文件 SHA 相等、仅源码顺序使 Linux 规则校验失败的原始问题，结果见 `rc7-posix-sort-reproduced.json`。新包需独立解压、核对全部文件 SHA、中文路径、源码和两端页面身份，并与 RC7 逐文件比较两端 `dist` 字节；完整结果见 `rc8-package-verification.json`。以上验证原始结果保存在忽略的 `.qa/production-fixes-20261018/`。

本机没有可直接运行的 Linux 环境。POSIX 路径语义模拟不能替代服务器实测；正式启动前仍须在雨云目标目录用已确认的 Node 24.22.0、`www` 身份执行只读发布校验，并要求 `verified:true` 且身份与包清单相同。

## 继续发布

- 新包：`outputs/production-fixes-20261018/studio-production-fixes-20261018-rc8.tar.gz`；SHA、身份和 Git 提交见同名 `.sha256`、`.manifest.json`。
- 新目录：`/www/studio-app-20261018-rc8`。RC7 失败现场和原 `/www/studio-app` 先保留，不在原位置覆盖。
- 包根目录没有外层文件夹，只能明确解压到新目录，不能直接在 `/www` 根目录解压。
- `/www` 已误解压的文件需按实际文件归属、可信包清单逐项核对和备份后处理；尤其 `/www/server` 是宝塔既存目录，不可整目录删除或移动。
- 校验失败就停止。不要在服务器执行 `--record`、`pnpm ops:release` 或手工修改清单使错误消失。
- 新根目录安装一次锁定的工作区依赖即可；页面沿用已构建产物，不追加旧静态文件改变发布身份。
- 继续保留宝塔注入的私有环境变量，数据库显式绑定 `/www/studio-app-data/studio.sqlite`；不要因新目录创建空库。
- 正式切换前仍需停写、一致性备份、离线恢复演练和兼容性检查。当前未替用户在服务器完成这些步骤，也未切换正式服务。

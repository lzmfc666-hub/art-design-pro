# 打手端 1.0 本地交付与上线准备

记录日期：2026-10-13，北京时间。需求依据：[上线需求与对接说明](./打手端上线需求与对接说明-v1.0.md)。

本次结构修订按用户后续澄清执行：打手端独立开发、独立前端端口、独立构建包，再对接现有后台 API；原需求说明中“增加在后台前端工程内”的结构方向已被此确认替代，业务规则继续沿用。

## 当前交付状态

已完成手机端与真实业务接口的本地实现和联调；尚未部署正式环境。当前没有正式域名、服务器、HTTPS 地址及中国大陆安卓/iPhone 实测证据，不能据此宣布正式上线或关闭网页后的推送必达。

参考源码基线为 `61892e086b9ec86971a20aa659657f548a7f7923`，当前开发工作区为 main；本次修改尚未提交或创建发布标签。现有用户需求文件和原输出目录保留，本地业务库没有被删除或替换。验证使用独立内存库/临时数据库和测试账号，不向本地业务库混入联调订单。

手机工程：`player-client/`，入口 `http://127.0.0.1:3008/#/player/login`，产物 `player-client/dist/`；管理后台 `http://127.0.0.1:3006/#/auth/login`，产物根目录 `dist/`；共同对接业务接口 `http://127.0.0.1:3007/api/studio`。打手端没有后台页面/组件依赖，可以单独复制、安装、构建和发布。手机用 `127.0.0.1` 会访问手机自身，正式使用必须使用部署后的 HTTPS 地址。

两端会话分别使用 HttpOnly Cookie，同一浏览器可同时登录管理员与打手且退出互不影响。独立打手代理只转发打手 Cookie，登录渠道只接受打手角色。旧手机路由只跳转到新的独立端，首次进入需要重新登录。旧嵌入源文件保存在 `.qa/embedded-player-before-split-v1/` 作为本地回溯资料，已退出后台构建；新工程中保留同样的页面与业务能力。

账号由原后台创建，设置打手等级、密码和三个独立开关。手机不开放注册；忘记密码由后台重置。禁止接单仍可完成已有任务；禁止提现不改变历史资金。

## 已实现的范围

- 手机四页：接单大厅、我的任务、排行榜、我的。蓝白单列卡片、底部导航、安全区域、加载/空数据/失败重试、断网提示与恢复、切换导航保留滚动位置。
- 本人指定单接受/拒绝、等级公共抢单、个人执行上限；退单申请占用名额，客服批准/驳回和待分配承接，保留拒单与退单历史。
- 完成截图、实际队友和财务验收；负责人多 1 分的奇数分分账；后台免图更正显示真实来源，过期操作拒绝，冲正和人工差额继续沿用原账本。
- 本人资料/头像/密码、私人收款码、每笔提现快照；正数最低 1 分、手续费 0、自然周 7 次、申请/撤回幂等、待审核撤回和财务审核竞争保护。
- 本人钱包和可解释账单，报酬更正采用独立变动流水；旧数据仅显示当前更正后历史余额快照，不补造原始收入历史。独立押金与报酬分开，押金明细分页读取。
- 有效完成负责人接单榜、按真实登记发放月份的提现榜、月份选择、并列名次与我的排名。
- 服务端站内消息、指定 5 分钟超时提醒客服、前台 15 秒核对数据、后台 30 秒提醒任务、持久推送队列和浏览器通知订阅。
- 配套后台待分配/退单待办筛选、处理记录、提现撤回状态/收款码快照、审计、37 模块导出与只读数据检查。
- 打手 API/附件/报表按本人范围约束；即使有后台权限覆盖，仍不能借手机接口读取客户付款、联系方式、工资、利润或他人收款资料。

接口与数据口径见 [共享契约](./STUDIO-CONTRACT.md)，服务配置见 [后台服务说明](../server/README.md)。首版不接企业微信、普通微信消息、短信或原生 App。

## 数据兼容与备份

原业务 JSON 基础 schemaVersion 保持 2；新字段采用兼容默认，不清空旧记录。新增 `dispatchState/returnRequests/rejections`、提现 `canceled/paymentSnapshot/weekStart/requestId`、本人付款资料、头像和报酬解释流水。旧 pending 订单默认 ready，旧提现没有快照时明确显示历史资料未知；旧报酬变动无法重建时显示历史余额快照。

新增 SQLite 表：`player_private_uploads`、`player_notifications`、`player_notification_settings`、`player_push_subscriptions`、`player_push_outbox`，启动时仅添加缺失表和索引。图片仍在原 uploads BLOB 表，资金账本、审计、账号和会话仍在同一数据库。通知与业务事件共同提交或回滚，任务重启后扫描恢复。

完整备份包含敏感业务数据，需要放在受控目录；日志导出不能替代全库备份。备份命令：

```powershell
node scripts/studio-backup.mjs .data/studio.sqlite .data/backups/studio-2026-10-13.sqlite
```

目标文件必须不存在，命令生成 SQLite 和元数据 JSON，检查 SQLite 完整性。正式迁移先在隔离副本上启动服务并验证账号、订单、钱包、押金、附件及权限。恢复时先停止业务服务并另存当前数据库，再恢复副本；恢复后清除备份中的旧 sessions 和旧推送订阅/待发队列，再启动并让用户重新登录、绑定通知，防止恢复旧认证状态。此步骤需在隔离恢复副本和正式恢复窗口内执行，不能对仍在线的测试/正式库直接操作。

## 正式发布前必须补齐

1. 确认服务器与域名，配置 HTTPS、持久数据库目录、受控备份目录和服务持续运行方式。反向代理和可信 Origin/Cookie 配置按服务说明核对，不能用临时内存数据库。
2. 先备份当前测试环境，再另外创建正式业务库，`STUDIO_DEMO=false`；配置正式管理员、人员、等级、平台、店铺与财务方案。不能把测试订单、测试余额或示例账号当正式业务，也不能直接删除当前本地环境。
3. 配置 `STUDIO_SECURE_COOKIE=true` 和必要可信 Origin，按实际访问位置核实服务器连通与合规条件。
4. 为网页推送配置 VAPID 公私钥和 subject，私钥只放服务端秘密配置；未配置时站内消息正常，页面明确显示未开启。关闭网页/锁屏提醒仍是首版需求，不能静默删去。
5. 中国大陆真实安卓/iPhone 测试：添加到桌面、允许/拒绝通知、关闭网页、锁屏、不同网络、系统限制、退出换号和跳转过期订单。记录型号/系统/浏览器、成功和失败场景，由用户确认可接受的支持范围。
6. 在正式机器按约 10 人常态并发复验，包含实际大截图上传、排行榜和资金竞争；完成数据库备份恢复演练，再提供真实访问地址与简明使用说明。
7. 提交本次源码并记录 1.0 实际发布提交/标签、构建产物与环境配置名称。当前工作区或 localhost 不作为正式发布证据。

独立端的日常启动、后台端口配置、代理认证和单独发布见 [独立打手端工程说明](../player-client/README.md)。生产需要同时配置独立端 `STUDIO_API_TARGET/VITE_ADMIN_URL`、后台 `VITE_PLAYER_CLIENT_URL/STUDIO_ALLOWED_ORIGINS`，保存两端实际发布版本的配套关系。

苹果主屏幕 Web App 推送自 iOS/iPadOS 16.4 起有系统、添加桌面和用户主动授权条件，见 [WebKit 官方说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。浏览器能力及推送服务网络条件见 [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)、[Firebase 网络说明](https://firebase.google.com/docs/cloud-messaging/network-configuration)。使用的服务器发送库说明见 [web-push 官方仓库](https://github.com/web-push-libs/web-push)。这些资料不证明实际中国大陆设备到达率。

## 1.0 回滚和 2.0 升级

上线前保存实际发布源码提交、完整数据库备份、构建包和配置项清单；不在文档中写真实密码或私钥。2.0 从真实发布提交及最新契约开始，在隔离数据副本验证迁移和回滚，再回归接单、退单、免图更正、奇数分结算、提现撤回/周限额、排行榜及后台关键流程。

当前变更为添加式兼容，但旧后台代码不认识 canceled/unassigned，也不支持奇数分双人报酬。产生新交易后不能只切回旧代码，更不能直接覆盖旧备份而丢失新订单与资金记录。回滚优先部署仍能读写这些状态和字段的兼容修复版本；若必须恢复旧版本，停写、另存最新库、逐项制定状态/资金迁移并验证，保留所有正式历史。

前端 HTML 和通知 worker 不长期缓存，worker 不离线缓存 API、截图、收款码或资金写入；打开旧页面的资金请求缺 requestId/收款方式会被当前服务器拒绝。升级时提示用户刷新并重新确认操作，不将不安全旧请求解释成成功。

## 日常操作和下一步

已安装任务名`Studio-Local-System`，私有运行目录`.qa/local-service`。在项目目录执行（不修改全局执行策略）：

```powershell
node scripts/studio-guardian.mjs --status
node scripts/studio-monitor.mjs --config .ops/local-monitor.json --status
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/studio-service-windows.ps1 -Action Status -TaskName Studio-Local-System -RuntimeDirectory .qa/local-service
# 停止/启动/卸载：将Status分别替换成Stop/Start/Uninstall，先核对项目和同一任务身份。
```

日常根目录启动入口可复用已运行进程。不要再以独立Start-Process启动第二个monitor，不按node名称批量结束程序。停止整个本机服务用任务Stop，会先Disable周期触发，再退出自己的家族；单独结束子端会触发有限恢复。物理开机尚未验证；任务已登记开机触发不等于已实测重启。

用户目前需要补的外部输入：服务器/域名采购预算与地区及购买账号、安全连接方式；告警渠道和接收目标（测试已同意但目标缺失）；独立备份存储与正式丢失/恢复时间目标。业务范围不清楚时默认保留全部数据和账号，不猜期初余额；正式启用账号、模板价格报酬和期初资金仍由业务/财务核实。打手端接入及联合验收由本任务统一处理，真实手机和收付款需用户配合。
